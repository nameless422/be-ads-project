# Workflow

这套工作流适合复杂需求。小改动可以合并阶段，但不能跳过边界：需求要清楚、方案要能落地、实现要被审查、结果要能验证。

## 阶段

| 阶段 | 负责人 | 输入 | 输出 | 下一步 |
| --- | --- | --- | --- | --- |
| 0. PM 路由 | PM | 用户诉求、task-board、dev-map | 任务编号、阶段、下一角色 | 需求分析或直接开发 |
| 1. 需求分析 | 需求分析 | 用户诉求、历史任务、相关 docs | SPEC 或结构化需求 | 方案设计 |
| 2. 方案设计 | 方案设计 | SPEC、dev-map、现有代码 | 技术方案、影响面、验证计划 | 闸门总控 |
| 3. 闸门总控 | 可行性分析 | SPEC、方案、当前仓库状态 | 放行 / 打回 / 阻塞项 | 开发实现或回退 |
| 4. 开发实现 | 开发 | 放行后的方案 | 代码、脚本、文档同步变更 | 代码审查 |
| 5. 代码审查 | 代码审查 | diff、SPEC、方案 | 问题清单或通过结论 | 测试验证或回退 |
| 6. 测试验证 | 测试验证 | diff、验收标准、验证脚本 | 验证结果、剩余风险 | PM 收口 |
| 7. PM 收口 | PM | 审查和验证结果 | task-board 更新、交付摘要 | 完成或下一轮 |

## 回退规则

- 下游不能直接改上游结论。发现需求、方案、闸门结论有缺口时，记录阻塞项，由 PM 打回对应阶段。
- PM 只做路由、交接、回退和记录，不替专业角色写需求、定方案或改代码。
- 开发阶段发现方案不可行时，停止扩散改动，先回到闸门或方案设计。
- 验证失败优先把失败沉到脚本或验收清单，避免只在对话里记住。

## 角色边界

### PM

负责读取用户诉求、task-board 和当前阶段结论，判断流程前进、回退、暂停或收口，维护任务编号、文档入口和交付结论。PM 不替需求分析补需求，不替方案设计定技术方案，不直接修改代码，也不用个人判断覆盖脚本失败。

### 需求分析

负责把模糊诉求变成明确目标、范围、非目标和验收标准，标出前端、后端、数据、脚本、文档的影响面，并查 task-board 识别是否延续旧任务。需求分析不提前写实现方案，不把“可以、建议、最好、可选”这类无法验收的词作为关键要求。

### 方案设计

负责查 dev-map，给出落点、数据流、接口、脚本和文档改法，明确兼容性、回滚方式和验证计划。方案设计不私自改需求结论，不绕开现有 domain / application / infrastructure 分层新建平行结构。

### 闸门总控

负责判断需求和方案是否足够进入开发，识别跨模块、数据一致性、运行环境、前端源码等风险，给出放行、打回或暂停等待人工确认的结论。闸门不补写需求或方案，不把高风险任务伪装成小改。

### 开发实现

负责按通过闸门的方案改代码、脚本和文档，保持改动贴近已有结构，对新增规则优先脚本化。开发不顺手重构无关模块，不回退用户已有改动，不把 `fe/dist` 或 `node_modules` 当成前端源码。

### 代码审查

负责对照 SPEC 和方案检查实现完整性，检查模块边界、错误处理、配置、数据流、兼容性和文档同步，输出按严重程度排序的问题。代码审查不只看格式，也不用“能跑”替代需求一致性。

### 测试验证

负责执行 `make harness-check`，根据影响面追加 `make test`、`make frontend-build`、`make verify`、`make verify-debezium` 或浏览器验证，并记录未跑项和原因。测试验证不把失败归为历史问题后直接放行，不用局部手工观察替代统一验证入口。

## 阶段文档

复杂任务放在：

```text
docs/harness/tasks/YYYYMMDD-<slug>/
  01-spec.md
  02-design.md
  03-gate.md
  04-review.md
  05-validation.md
```

轻量任务可以只更新 `task-board.md`，但如果涉及跨模块、跨前后端、数据链路或真实平台账号，必须补 SPEC 和验证记录。

## 前后端任务分流

- 纯后端任务：优先查 `be/internal/modules/*`、`be/cmd/*`、`be/scripts/*`，验证从 `make harness-check` 开始。
- 纯前端任务：源码入口是 `fe/package.json` 和 `fe/src`；不能把 `dist` 当成长期维护入口。
- 前后端联动任务：SPEC 必须写明 API 路由、字段、错误态、页面入口、验证命令和本地联调方式。
